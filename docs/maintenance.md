# “整理”工作流

以后在本仓库的任务中说 **“整理”**，含义是：把自上次整理以来真正学过、操作过、遇到并解决的问题，按统一模板更新成课程文件。

## 一次整理需要完成什么

| 顺序 | 动作 | 产物 |
|---|---|---|
| 1 | 阅读更新记录、当前 Lesson 和环境台账 | 确定上次边界，避免重复 |
| 2 | 从新增对话提取操作、反馈、问题、决策 | 有证据的事实清单 |
| 3 | 区分已完成、计划、暂缓、跳过、待验证 | 不把建议写成成果 |
| 4 | 按[固定模板](templates/lesson-template.md)合并或新建 Lesson | 保留原理、命令、原因、验证 |
| 5 | 同步[环境台账](environment.md)、[路线图](roadmap.md)、Phase 概览和导航 | 网站各页状态一致 |
| 6 | 更新[更新记录](changelog.md)的范围和未决项 | 下一次可接着维护 |
| 7 | 严格构建；主题变化时检查桌面和窄屏 | 可浏览的静态网站 |
| 8 | 已连接并可写入远程时推送，检查部署结果 | 分开报告本地与线上状态 |

## 证据优先级

用户明确反馈 / 对应操作实际输出 > 有来源的历史总结 > 助手建议。建议与预期输出永远不能独立证明操作完成；无法读取的截图要标明限制。

只改变有新证据的条目。初次记录中的 Python 3.14.7 是历史反馈，不能顺手替换成助手认为更合理的版本；如有新验证，追加更正和来源。

## 文件约定

- 阶段：`docs/phases/XX-topic/index.md`。
- 课程：`docs/phases/XX-topic/YY-lesson.md`。
- 标识：`PXX-LYY`，路径建立后尽量保持稳定。
- 新增页面后更新 `mkdocs.yml`，不只创建一个无法从导航进入的文件。
- 课程可先进行中；完成的知识和操作与待办并列保存。

## 如何在新对话继续

把 `ai-engineering-abel` 作为项目打开，或把仓库和新增学习记录提供给助手。仓库中的 `AGENTS.md` 会说明维护规则。若新助手不能访问之前的对话，只整理可读取的部分，把缺失证据列出来，不凭记忆补齐。

“整理”是维护约定，不是已经建立的后台定时任务。网页自动更新依赖提交推送到 GitHub，并且 Pages 部署成功。只有本地文件改变时，报告“本地已整理，待发布”。

## 何时结课

必要操作有实际反馈、验证标准满足、关键概念经过用户确认或自测，才能将 Lesson 状态改为已完成。不能以文档写完代替学习完成。

## 原课练习与测验的保存约定

每次“整理”保留已学内容的概念、实操、问题、解决过程和验证证据，同时收录对应章节的练习与测验。

| 保存项 | 保存方式 |
|---|---|
| Exercises | 原样保留练习要求、代码与子问题 |
| Test your understanding | 原样保留；若只是网页说明或未找到独立内容，注明核对状态 |
| Post-Lesson Quiz | 原题、选项顺序、原答案和解释；答案默认折叠 |
| 我的作答 | 保留首次回答、订正、结果和错因，不用原答案覆盖 |
| 我们的补充 | 单独标记翻译、解析、Mac 适配或原题纠错，不改写原题 |

已核对原课程本地版本采用 MIT 许可；转载时保留版权与许可全文，并记录来源、版本及收录日期。后续章节如有单独许可，以实际文件为准。缺失内容标为待核对，需要时补充原文或截图；不编造题目，不自动把未作答标成通过。仅整理已学章节，不批量搬运全部课程。

每课使用独立练习页并链接回笔记，保存原始资料快照。示例：[Lesson 01 原课练习与测验](phases/00-setup-and-tooling/01-dev-environment-practice.md)。
